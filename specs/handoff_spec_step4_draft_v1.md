# HAND-OFF SPEC: STEP 4 — B' 对照实验

## 给 Claude Code 的话
继续 STEP 3 的 interpretability 实验。这一步加一个新对照组 B',用来分离两件之前被混在一起的事:
"对话形式本身的差异" vs "对'谁'的表示差异"。
原则不变:先问、不要替我做核心设计决定;跑出结果给我看,我审了再继续。

---

## 这一步要回答什么问题

STEP 3 的结果显示 A+↔B(纯形式)有可观差异。但那个差异里混着两样东西:
1. **对话结构差异**(B 是来回问答 + accept/reject,A+ 是平铺陈述)
2. **对 Alex 这个人形成的表示差异**(可能,也可能没有)

光看 A+↔B 没法区分这两者。所以引入 B':
- B':和 B **完全相同的对话结构、完全相同的回合数、完全相同的 accept/reject 模式**,
  但里面的人是 **Sam**,带 **完全不同的三条偏好**。

然后看 **B↔B'**(同样是对话,只是人不同):
- 如果 **B↔B' 也很大**(接近 A+↔B):模型在表示"**这是谁**"——质地假设得到更强支持
- 如果 **B↔B' 很小**(接近零):模型只在表示"这是段对话",形式差异不来自人——质地假设在这个尺度上没有证据

两个结果都是有用的 claim,不是成功/失败问题。

## STEP 4.1 — 我需要先确认的核心设计决定(请先问我)

请把下面这三件事整理好问我,**不要自己替我假设**:

### 1. Sam 的三条偏好(必须和 Alex 的三条完全不重叠、彼此正交)
Alex 的三条(参考):
- 喜欢简短回答
- 喜欢先给结论再给理由
- 犹豫时希望被推一把,不是被给更多选项

Sam 的候选三条(请确认 / 让我替换):
- 喜欢用类比和故事来解释,不喜欢干巴巴的事实
- 倾听时希望先得到情绪共鸣,再听具体建议
- 决策时希望被给更多选项展开,而不是被推向某一个

**要点:Sam 的偏好在某些维度上必须和 Alex 的**反着来**(比如 Alex 要"被推一把",Sam 要"更多选项")——这样如果模型真的在表示"人",B 和 B' 的表示应该清楚地分开。

### 2. 对话场景的对应性
B 用的是三个场景:解释概念(复利)、做决策(工作 offer)、做选择(搬家)。
B' 应该:
- (a) 用**同样的三个场景**(复利、工作 offer、搬家),让 Sam 在同样的语境里展现不同偏好——**变量更干净**
- (b) 还是 (a),但场景类型对应即可(解释类、决策类、选择类),具体话题可以换

我倾向 (a),变量最干净。请等我确认。

### 3. 回合数和长度对齐
B 当前 ~272 token。B' 必须**严格控制在 ±10 token 以内**,否则又会引入长度差异。
请按 6 轮往返结构(三场景 × 每场景 2 轮)对齐,跑完后输出 token 数核对。

## STEP 4.2 — 起草 B'(等我确认 4.1 三件事后再做)

按确认后的偏好和场景写 B'。结构镜像 B:
```
Sam: [场景 1 提问] 
Assistant: [一个故意"错"的回答——和 Sam 的偏好相反]
Sam: [纠正语句,直接复用偏好的关键词]
Assistant: [纠正后的回答]
Sam: Better.

...重复三场景
```

**关键控制:**
- 纠正语句要复用 Sam 偏好的关键词(类比的方式:对应 Alex 的 "short";"分析感受 first" 对应 Alex 的 "conclusion first";"more options" 对应 Alex 的 "push toward one")
- accept/reject 信号("Too X" / "Give me Y instead" / "Better")结构和频率与 B 保持一致

草稿先给我审,我盯一件事:**B 和 B' 是否真的只差"这个人是谁",其他变量是否都对齐**。

## STEP 4.4 — 记录新的 limitations(写在脚本注释和输出里)

继承 STEP 3 的两条:
- L1: B 和 B' 都是"在对话中陈述",不是真正的"经历"
- L2: A+ 和 B 的偏好密度未控

新增可能的:
- L3: GPT-2 small (124M) 可能太小,不足以形成对"人"的稳定表示——如果 B↔B' 很小,这是合理的解释之一,不一定是质地不存在,而是显微镜不够强
- L4: B 和 B' 的"人"差异可能被部分编码为 token 层面差异("Alex" vs "Sam" 这两个名字本身就有不同的 embedding)——这是后续需要进一步控制的混淆(比如用同一个名字、只换偏好内容)
